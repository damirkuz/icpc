# B — восстановление римской строки одним запросом

`Main.java` — интерактивное решение для Java 8. Оно выводит `? I`, сбрасывает
буфер, читает ответ жюри и выводит `! s` со сбросом буфера. Делается ровно
**один запрос**, даже если одна позиция искажена. Обычного входного файла
с исходной строкой у этой задачи нет.

## Какие блоки возможны

Любое четырёхзначное число из исходной строки больше 3999. Поэтому блок
содержит от одной до трёх десятичных цифр:

| Блок | Римская запись | Расстояния между `I` |
|---|---|---|
| 6 | VI | 2 |
| 7 | VII | 2, 1 |
| 67 | LXVII | 4, 1 |
| 76 | LXXVI | 5 |
| 676 | DCLXXVI | 7 |
| 767 | DCCLXVII | 7, 1 |

Перед первым символом считаем, что предыдущая `I` находилась в позиции −1.
Каждый блок заканчивается на `I`, поэтому таблица расстояний одинакова
для первого и всех следующих блоков. Например, для `VIVII` позиции равны
`[1,3,4]`, а расстояния — `[2,2,1]`.

Отдельная цифра 6 даёт два символа, 7 — три. Это сохраняется и при объединении
цифр в каждый из шести блоков, поэтому `|s|=5n≤5000`; число `I` не больше 3000.

## Автомат для правильных расстояний

Достаточно трёх состояний:

- `S6`: следующий десятичный блок начинается с 6;
- `S7`: следующий блок начинается с 7;
- `T`: осталось прочитать вторую `I` блока, заканчивающегося на 7.

| Состояние | Расстояние | Добавить к строке | Следующее состояние |
|---|---|---|---|
| S6 | 2 | VI | S7 |
| S6 | 4 | LXVI | T |
| S6 | 7 | DCLXXVI | S7 |
| S7 | 2 | VI | T |
| S7 | 5 | LXXVI | S7 |
| S7 | 7 | DCCLXVI | T |
| T | 1 | I | S6 |

Начальное и принимающее состояние — `S6`. Непустая принятая строка
соответствует последовательности десятичных цифр `67`, повторённой
целое положительное число раз. Другие переходы запрещены.

## Почему одной ошибки недостаточно для неоднозначности

Сравним два разных правильных возрастающих списка позиций `I` одинаковой
длины. Рассмотрим первую различающуюся позицию. До неё состояния автоматов
совпадают, поэтому расстояния выбираются из одной строки таблицы:

- для `S6` возможны 2, 4, 7;
- для `S7` — 2, 5, 7;
- в `T` выбора нет.

Первое различие позиций имеет модуль хотя бы 2. Если оно больше 2,
сумма модулей различий уже не меньше 3.

Если различие равно 2, это пара 2/4 в `S6` или 5/7 в `S7`. После меньшего
расстояния автомат находится в `S7`, после большего — в `T`. Ни одно из
этих состояний не принимающее: следующая `I` обязательно существует.
Чтобы её позиции совпали, из `S7` потребовалось бы расстояние 3,
поскольку из `T` единственное расстояние равно 1. Расстояния 3 нет.
Значит, следующая позиция тоже различается хотя бы на 1.

Итак, расстояние L1 между любыми двумя правильными списками не меньше 3.
Ответ жюри отличается от настоящего списка по L1 не больше чем на 1.
Если бы один ответ соответствовал двум строкам, расстояние между их
правильными списками было бы не больше 2 — противоречие.

Сортировка ответа безопасна: сдвиг целой позиции на единицу может сделать
её равной соседней, но не может перескочить через соседнюю. После сортировки
по-прежнему достаточно исправить одну координату на единицу. Повторяющиеся
позиции в ответе удалять нельзя.

Ноль запросов недостаточно: например, `VIVII` и `LXVII` — две допустимые
строки уже при `n=1`. Поэтому один запрос оптимален. Доказательство
однозначности действует и против адаптивного интерактора.

## Как найти исправление быстро

Пусть `g[i]` — расстояния, вычисленные из полученного списка. Исправление
позиции `i` на `delta∈{−1,+1}` меняет только:

```text
g[i]   += delta
g[i+1] -= delta     // если следующая позиция есть
```

Вычисляем состояние автомата после каждого префикса. Для каждого суффикса
и каждого из трёх состояний вычисляем, можно ли из него завершить строку.
Теперь каждое возможное исправление проверяется двумя переходами автомата
и одним обращением к таблице суффиксов. Если исходный список уже правильный,
исправление не требуется. Из доказанной однозначности следует, что найденная
строка и есть ответ.

После сортировки декодирование занимает `O(m)` времени и памяти, где `m`
— количество `I`; с сортировкой — `O(m log m)` времени. Вывод имеет длину `5n`.

## Проверка

Запуск из каталога `icpc`:

```bash
python3 six-seven/tests/stress_b.py
```

Эталон строит **все разбиения десятичной строки**, а числа переводит в
римскую систему общим жадным алгоритмом для значений до 3999. Таблицу
переходов основного решения он не использует.

Прогон с seed `67067` проверил:

- 1315 различных строк для всех `1≤n≤6`;
- все 29 959 различных ответов жюри для этих строк, включая каждый сдвиг
  каждой позиции в обе стороны и ответы без искажения;
- 2000 случайных строк, в том числе с `n=1000` и перемешанными позициями;
- 40 больших граничных случаев: дубликаты, ошибки в начале/середине/конце,
  позиция после последнего символа, обратный порядок входных позиций;
- 30 настоящих интерактивных запусков Java через каналы процесса:
  программа начинает взаимодействие сама, выполняет ровно один запрос,
  делает `flush`, выводит правильную строку и завершает работу.

Всего 32 005 проверок декодера заняли 0.174 с в Java вместе с вводом/выводом;
самый медленный интерактивный процесс — 0.030 с. Окружение: OpenJDK 25.0.2,
компиляция с `--release 8`, Python 3.14.0. Это локальные измерения, не время
на сервере соревнования. Перед реализацией тест отклонил заглушку,
постоянно возвращавшую `LXVII`, на правильной строке `VIVII`.

Проверено локальным имитатором; запуск на настоящем интеракторе соревнования
не выполнялся.
