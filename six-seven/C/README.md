# C. 6-7-city

Решение: `Main.java`, Java 8, `public class Main`, без `package`.

## Идея

Строим неориентированный граф домов по условию. У каждого дома не более четырёх соседей; пятое возможное действие — остаться на месте.

Для BFS храним состояние `(v, d, r)`:

- `v` — текущий дом;
- `d = 0..6` — день недели **следующего действия**, где `0` — понедельник;
- `r = 0..6` — количество уже выполненных возвратов в текущей неделе.

Начальное состояние — `((1, 1), 0, 0)`. Проверять понедельничный запрет начального дома заранее нельзя: в понедельник разрешено сразу уйти из него.

Для каждого действия из `v` в `u`:

1. Проверяем, что в `u` можно ночевать в день `d`.
2. Если номер улицы уменьшился, прибавляем к `r` единицу. Значение больше шести запрещено.
3. Переводим день на следующий. После воскресенья сбрасываем счётчик возвратов в ноль. Проверка воскресного возврата выполняется **до** сброса.
4. Добавляем ещё не посещённое состояние в очередь BFS и запоминаем предка.

Первое извлечённое из очереди состояние в доме `(n, 6)` даёт ответ. По предкам восстанавливаем все `k + 1` домов, включая старт. Если подходящее состояние не найдено, выводим `-67`.

## Доказательство

**Состояния достаточно.** Расписание повторяется каждые семь дней. Все будущие допустимые действия определяются текущим домом, днём следующего действия и уже использованными возвратами этой недели. Более ранняя история и номер недели не влияют на продолжение маршрута.

**Переходы точны.** Добавляются только ожидание или переход по ребру графа. Проверка назначения обеспечивает допустимую ночёвку, а проверка счётчика и сброс после воскресенья — ограничение календарной недели. И наоборот, каждое допустимое действие проходит эти проверки. Поэтому маршруты исходной задачи и пути из начального состояния взаимно соответствуют.

**Ответ минимален.** Каждое ребро состояний соответствует ровно одному действию. BFS обрабатывает состояния по неубыванию количества действий, поэтому первое достигнутое целевое состояние имеет минимальную длину. Предки восстанавливают путь этой длины. Если ни одно целевое состояние не достижимо, допустимого маршрута нет.

## Сложность

Количество домов `H = (13n - 1) / 2`. Выделяется `49H` состояний; из каждого проверяется не более пяти действий. Время и память — `O(49H) = O(n)`, включая восстановление и вывод пути.

При `n = 4489` получаем `H = 29178` и `1429722` слота состояний. Очередь и предки занимают вместе около 10,9 МиБ. Все числовые массивы даже при пути длиной до числа состояний укладываются примерно в 18 МиБ; это оценка массивов, без накладных расходов JVM.

## Проверка

Из корня `icpc`:

```bash
python3 six-seven/tests/stress_c.py --cases 10000 --seed 670067 --perf
```

Тест компилирует решение с `javac --release 8`, используя временный каталог. Эталон независимо строит рёбра проверкой пар домов и выполняет BFS по явным кортежам. Для каждого ответа сверяется минимальная длина, затем отдельно проверяются начало, конец, существование домов, соседство, расписание каждой ночи и возвраты каждой календарной недели. Цифры запретов во входе перемешиваются.

Проверено 10010 случаев: 10000 случайных при `n = 3..13` и 10 фиксированных. Фиксированные включают три примера из условия (`10`, `17`, `-67`), закрытый старт, первый понедельник, недоступную цель, использование седьмого дома чётной улицы и два специальных календарных случая:

- Семь вынужденных возвратов в одной неделе: правильный ответ `-67`, при разрешении седьмого возврата появляется путь длины `22`.
- Ожидание переносит последний возврат на следующий понедельник: правильный ответ `23`, без сброса счётчика маршрут недоступен.

Дополнительно собраны три изменённые копии решения: с разрешённым седьмым возвратом, без недельного сброса и со сдвигом первого действия на вторник. Фиксированные тесты обнаружили все три ошибки.
