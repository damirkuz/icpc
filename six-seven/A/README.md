# A — остаток последовательности 6, 7

`Main.java` — отдельное решение для Java 8: `public class Main`, без `package`.
Для каждого запроса строится индекс за `O(k)`; для всех допустимых нечётных
`x` решение существует, поэтому выводить `-67` не требуется.

## Идея

Пусть `v_n = (F_n, F_(n+1))^T`, тогда

```text
v_(n+1) = M v_n,       M = [0 1]
                          [1 1]

p_b = 3 · 2^(b−1).
```

Для любого `b ≥ 2` верно

```text
M^p_b ≡ (1 + 2^b) I  (mod 2^(b+1)).
```

Доказательство по индукции. Для `b=2`:

```text
M^6 = [5  8] = I + 4 [1 2] ≡ 5I (mod 8).
      [8 13]         [2 3]
```

Если `M^p_b = I + 2^b B`, где `B ≡ I (mod 2)`, то

```text
M^p_(b+1) = (I + 2^b B)^2
          = I + 2^(b+1) (B + 2^(b−1) B^2).
```

При `b ≥ 2` матрица в скобках снова равна `I` по модулю 2.
Следовательно, если `F_n` нечётно, то

```text
F_(n+p_b) ≡ F_n + 2^b (mod 2^(b+1)).
```

Сдвиг на `p_b` сохраняет биты с номерами `0..b−1` и меняет бит `b`.

## Алгоритм и корректность

1. Если `x mod 4 = 3`, начинаем с `n=1`, `F_1=7`, `F_2=13`.
   Иначе начинаем с `n=2`, `F_2=13`, `F_3=20`.
   Для нечётного `x` это сразу даёт правильный остаток по модулю 4.
   При `k=1` единственный запрос имеет `x=1`, и индекс 2 также подходит.
2. Для `b=2..k−1` сравниваем бит `b` текущего `F_n` с битом `x`.
   Если биты различаются, прибавляем к индексу `p_b` и умножаем пару
   `(F_n, F_(n+1))` на заранее вычисленную матрицу `M^p_b`.
3. После итерации `b` совпадают все младшие `b+1` бит. Поэтому после
   последней итерации `F_n ≡ x (mod 2^k)`.

Таким образом, любой допустимый нечётный остаток достижим.
При `k≥2` начальный индекс меньше `p_2`; каждый шаг сохраняет
`0 ≤ n < p_(b+1)`. В результате

```text
0 ≤ n < 3 · 2^(k−1) ≤ 3 · 2^59 < 2^61 < 2^64.
```

Индекс помещается даже в обычный знаковый `long`.

## Арифметика и сложность

Матрицы получаем последовательным возведением в квадрат и храним по модулю
`2^60`. Все значения последовательности также храним по модулю `2^60`.
Переполнение `long` при умножении намеренное: Java сохраняет младшие 64 бита,
а маска `(1L << 60) - 1` оставляет ровно требуемые 60 бит. Поскольку
`k≤60`, потерянные старшие биты ни на что не влияют.

Предподсчёт: `O(60)` времени и памяти. Один запрос: `O(k)` времени и `O(1)`
дополнительной памяти. Общая память — `O(60 + q)` с учётом буфера вывода.

## Проверка

Запуск из каталога `icpc`:

```bash
python3 -u six-seven/tests/stress_a.py --small-k 18 --random 50000 --performance
```

Скрипт компилирует решение с `javac --release 8` во временный каталог.
Проверка независима от подъёма по битам: для малых модулей цикл
последовательности строится прямым сложением; для больших используется
удвоение индекса обычных чисел Фибоначчи на целых Python и равенство
`F_n = f_n + 6 f_(n+1)`.

Проверены:

- все 262 143 допустимых запроса при `1≤k≤18`;
- 75 473 граничных и случайных запроса, включая примеры условия,
  `k=1`, `k=60`, остатки около границ и цели от индексов во всём диапазоне
  `uint64`, а также 118 случаев с исправлением каждого следующего бита;
  фиксированный seed `676767`;
- максимальная пачка: 300 763 запроса, все с `k=60`, каждый ответ
  проверяется независимым вычислением `F_n mod 2^k`;
- ещё 300 763 запроса с `k=60`, в каждом из которых требуются все 58
  возможных сдвигов индекса.

До реализации тест ожидаемо отклонил заглушку, всегда печатавшую `-67`:
`query 1: k=1, x=1: unexpected -67`.

Локальное окружение: OpenJDK 25.0.2, компиляция в Java 8, Python 3.14.0.
Время Java включает запуск процесса и ввод/вывод; измерение на локальной
машине не является замером сервера соревнования.

| Проверка | Время Java |
|---|---:|
| Полный перебор `k≤18` | 0,064 с |
| Границы и случайные запросы | 0,048 с |
| Максимальное `q`, `k=60` | 0,136 с |
| Максимальное `q`, все 58 сдвигов | 0,081 с |

Независимая проверка всех ответов случайной максимальной пачки заняла 3,579 с.

После реализации отдельно проверены нижние границы `k=1,2`, верхняя граница
индекса, знаковое переполнение, порядок обновления пары и независимость
эталонной проверки от основного алгоритма. Нерешённых ошибок не найдено.
