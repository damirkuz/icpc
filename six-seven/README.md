# Решения A, B, C на Java

Каждый файл — самостоятельное решение с `public class Main`, без `package`
и сторонних библиотек. Код совместим с Java 8. В проверяющую систему нужно
отправлять **только один соответствующий `Main.java`**, без тестов.

| Задача | Код | Алгоритм | Разбор |
|---|---|---|---|
| A. 6-7-acci | [A/Main.java](A/Main.java) | Подбор индекса по битам, `O(k)` на запрос | [A/README.md](A/README.md) |
| B. 6-7-blocks | [B/Main.java](B/Main.java) | Один запрос `? I`, исправление ошибки конечным автоматом | [B/README.md](B/README.md) |
| C. 6-7-city | [C/Main.java](C/Main.java) | BFS по дому, дню недели и числу возвращений | [C/README.md](C/README.md) |

В A все допустимые нечётные остатки достижимы. Найденный индекс может
отличаться от примера — это разрешено. В C оптимальный маршрут также
может отличаться от приведённого в условии.

## Запуск

Например, для A из каталога `icpc`:

```bash
javac --release 8 -Xlint:-options six-seven/A/Main.java
java -cp six-seven/A Main < input.txt
```

Для C заменить `A` на `C`. B — **интерактивная** задача: она сама начинает
обмен запросом и ожидает ответа жюри. Её проверяет локальный интерактор
в `stress_b.py`; подавать ей обычный тест от A или C нельзя.

## Все стресс-тесты одной командой

Нужны Python 3 и JDK 9+ для компиляции с флагом `--release 8`.
Сами решения используют только возможности Java 8.

```bash
python3 -u six-seven/tests/run_all.py
```

Скрипты компилируют Java во временные каталоги и удаляют их после проверки.
Все генераторы и эталоны используют только стандартную библиотеку Python.
Для изменения объёма или seed можно запускать отдельные тесты:

```bash
python3 six-seven/tests/stress_a.py --small-k 18 --random 50000 --performance --seed 676767
python3 six-seven/tests/stress_b.py --small-max 6 --random 2000 --sessions 24 --seed 67067
python3 six-seven/tests/stress_c.py --cases 4000 --perf --seed 670067
```

- A: полный перебор малых модулей, независимое вычисление через числа
  Фибоначчи для больших модулей, максимальное число запросов, предельные
  значения и переполнение `long`.
- B: полный перебор разбиений коротких десятичных строк и всех одиночных
  искажений, длинные случайные строки, дубликаты и перемешанные позиции,
  отдельные процессы для проверки интерактивного протокола.
- C: независимый перебор состояний для малых городов, проверка каждого
  перехода выведенного маршрута, дней ночёвок и недельного ограничения;
  большие города и большое число наборов.

Доказательства и подробные результаты находятся в разборах задач.
Стресс-тесты проверяют локальную реализацию; отправки на сервер
соревнования и проверки B настоящим интерактором не выполнялись.
